# 新租 VPS → agent 配置 → Clash / 小火箭导入

这套 skill 的目标是“一次调用，完成可自动化的部署和导入文件准备”。手机安装应用、授予 VPN 权限、切换正在使用的 VPN，以及会影响联网的防火墙变更，需要在对应设备上完成或明确授权。

## 先确定归属

给新用户配置，必须租用属于该用户或团队的新 VPS，生成新密钥。不能使用 skill 作者的个人服务器、订阅、SSH 密钥或备用节点。公开仓库只放工具和说明；服务器 IP、客户端节点、二维码、管理员备份留在私有目录。

默认路径：客户端 → 新租的线路优化 VPS → 网站。线路优化是选购服务器的条件，不是固定绑定某家商家。新用户应根据自己所在地和运营商测试晚高峰、带宽和月流量。十多人下载数据时，不能把“端口带宽大”当成“每月流量够”。

需要中转时才增加：客户端 → 供应商入口 → 该用户自有 VPS → 网站。供应商永远只作入口；自有出口全部不可用就连接失败。

## 一次完整部署

1. **用户开新机器。** 选择支持的 Linux systemd 系统、地区和流量套餐，保存供应商控制台入口。购买和计费由用户决定；skill 不自动下单。
2. **提供最少信息。** 新 IP、系统和架构、SSH 用户/端口、该用户本地 SSH 密钥路径或已有 SSH 别名、从控制台核对的主机指纹、要使用的设备数量。只给 IP 无法登录。不要把 SSH 私钥正文贴到对话或 GitHub。
3. **agent 只读检查。** 核对机器身份、系统、端口、现有服务、时钟、网络和 REALITY 握手目标。先准备具体部署结果；不覆盖已有服务，不擅自关闭 SSH 密码登录或重置防火墙。
4. **生成独立凭据。** 每台新服务器一个新 REALITY 密钥，每台客户端一个新 UUID。生成服务端配置、各平台 Mihomo YAML、小火箭链接/二维码、单独的 iOS 规则文件。输出放到仓库外的私有目录。
5. **部署新服务。** 使用官方 sing-box 版本和校验和，先验证配置，再在已授权的新 VPS 上安装独立 systemd 服务。按需放行所选 TCP 端口；保留 SSH 和其他业务。默认端口为 9443，可在生成时改变。
6. **做隔离验证。** 先验证文件一致性，再用 TUN 关闭、独立本地端口的测试客户端检查连接、出口、DNS 和需要的 UDP 功能。测试全部出口不可达时连接失败。不能用“文件生成成功”代替真实联网测试。
7. **客户端导入。** Windows/macOS/Linux 选择相应的 Mihomo 配置。确认 GUI、全局脚本和最终运行配置没有覆盖规则。iOS 分别导入节点与规则，选择新用户自己的节点，检查当前版本的 DNS、隧道与按需连接设置。
8. **防泄漏验收。** 检查默认流量、自定义直连例外、DNS、IPv6 和 UDP。桌面系统防火墙与 TUN 是独立保护层。Windows 可以按本文配套说明制定并应用出站限制；macOS/Linux 需要各自的系统方案。iOS 必须在真机上验证，不能移植 Windows 防火墙。
9. **交付与撤销。** 给每台设备只交付自己的 `clients/clientNN` 文件夹。管理员保留服务器配置和部署记录。某个节点链接泄漏时撤销该 UUID，并与管理员安排服务更新；不要让所有人共用一个永久凭据。

## 调用示例

安装仓库中的 `skills/owned-vps-egress` 后，在 agent 中输入：

```text
使用 $owned-vps-egress，为新的使用者部署。
这是对方新租的 VPS，不使用我现有的任何个人节点。
新 IP：……；系统/架构：……；SSH 用户/端口：……。
SSH 密钥在本机的路径：……；已核对的主机指纹：……。
设备：Windows Clash Verge 和 iOS 小火箭，共 …… 台。
默认全部走新 VPS，需要直连的域名只有：……（没有则写无）。
先生成、检查部署方案与导入文件，不要切换当前正在使用的 VPN。
```

授权部署新服务器后，agent 按 `references/deployment.md` 执行。导入并激活本机新配置、安装系统出站限制，会影响当前连接，应明确指定设备和允许的动作。已授权的步骤无需反复确认。

## iOS 具体要做什么

1. 安装正版小火箭，记录应用版本和 iOS 版本。
2. 在小火箭里扫描自己的二维码，或者导入自己的 VLESS 链接。
3. 另行导入并选中 `shadowrocket-rules.private.conf`。二维码不包含这份规则。
4. 使用配置/规则路由，PROXY 选择刚导入的新自有节点，不要选旧机场节点或带 DIRECT 的回退组。
5. 核对 DNS 经代理、IPv6 捕获/拒绝、完整隧道和按需连接选项。不同版本可能有不同字段；以应用实际支持为准，不宣称导入文件自动设置了所有开关。
6. 分别在 Wi-Fi、蜂窝网络、切换网络和测试节点不可达时验收。VPN 图标亮着不足以证明防泄漏。手动关闭 VPN 后系统通常可以恢复直连，这不能描述成“仍受保护”。

skill 在具备 Python/SSH 的 agent 环境运行，通常是电脑。这里的 iOS 适配指客户端配置和验收流程，不是让普通 iPhone 自动执行服务器安装脚本。

## 防泄漏的边界

- **路由层：** 默认 PROXY，自有节点故障不回落到 DIRECT 或供应商出口；直连例外要明确列出。
- **DNS 层：** TCP/UDP 53 接管，应用 DoH 走代理，区分代理服务器的启动解析。只设置 DoH 地址并不自动证明其出口正确。
- **IPv6 层：** 不只是不返回 AAAA，还要捕获或阻断字面 IPv6 地址的流量。
- **系统层：** TUN/core 不在时仍要阻止绕过，需系统支持和实际验证。Windows 防火墙默认拒绝出站，但新增的应用放行规则可能削弱它。
- **运维层：** 客户端、Store 应用、网卡或其他 VPN 更新后复查。恢复网络应只尝试该用户的自有出口，不能把关闭防火墙作为默认修复。

## 发布 GitHub

公开仓库地址：https://github.com/SanN2Z/owned-vps-egress-kit 。只发布这个干净目录，不要发布它的上级工作区。运行公开文件扫描并核对待发布清单。仓库不包含真实用户的部署产物；`.gitignore` 也无法撤销已经提交过的秘密。后续更新仍需检查具体变更与发布授权。

其他机器可以直接对 Codex 说：

```text
使用 $skill-installer 安装 https://github.com/SanN2Z/owned-vps-egress-kit/tree/main/skills/owned-vps-egress
```

也可以复制该 skill 目录到 `~/.agents/skills/`。这是可重复调用的 skill；具体网络环境、系统权限和 iOS 真机验证仍然不可省略。
